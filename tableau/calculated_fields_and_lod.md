# Tableau Calculated Fields & Level of Detail (LOD) Expressions

This document contains the complete library of production-ready Tableau Calculated Fields, Level of Detail (LOD) Expressions, and Table Calculations developed for the **E-Commerce Sales & Customer Analytics** project.

All calculations are tested against the cleaned 48-transaction dataset (Net Revenue: **₹14,38,655**, Total Orders: **48**, AOV: **₹29,972**).

---

## 1. Core KPI Metrics (BANs - Big Ass Numbers)

### Total Revenue
Calculates the aggregate net sales revenue across all completed and valid orders.
```tableau
// [Total Revenue]
SUM([Revenue])
```
*Default Number Format: Currency (Custom) → Prefix: `₹`, Decimals: `0`, Display Units: `Thousands (K)` or `Lakhs`*

---

### Total Orders
Distinct count of unique order identifiers.
```tableau
// [Total Orders]
COUNTD([Order ID])
```
*Default Number Format: Number (Standard) → `#,##0`*

---

### Total Units Sold
Total quantity of physical items purchased.
```tableau
// [Total Units Sold]
SUM([Quantity])
```
*Default Number Format: Number (Standard) → `#,##0`*

---

### Average Order Value (AOV)
Revenue generated per individual order transaction.
```tableau
// [Average Order Value]
[Total Revenue] / [Total Orders]
```
*Alternative:*
```tableau
// [AOV (Direct)]
SUM([Revenue]) / COUNTD([Order ID])
```
*Default Number Format: Currency (Custom) → Prefix: `₹`, Decimals: `0`*

---

### Average Basket Size (Units per Order)
Average number of units contained in each transaction.
```tableau
// [Units Per Order]
SUM([Quantity]) / COUNTD([Order ID])
```
*Default Number Format: Number (Custom) → `0.0`*

---

### Net Discount Amount
Total currency amount saved by customers via discounts.
```tableau
// [Total Discount Given]
SUM([Quantity] * [Unit Price] * [Discount])
```
*Default Number Format: Currency (Custom) → Prefix: `₹`, Decimals: `0`*

## 2. Level of Detail (LOD) Expressions

Level of Detail (LOD) expressions allow you to compute values at the data source level and dimensional levels other than the view level (viz level of detail).

### Customer Lifetime Spend (LOD: FIXED)
Computes the total revenue generated by each customer across their entire purchase history, independent of any worksheet-level dimensions or category filters.
```tableau
// [Customer Lifetime Spend]
{ FIXED [Customer] : SUM([Revenue]) }
```
*Business Application: Used to segment customers into VIP tiers without the tier changing when filtering for a single month or category.*

---

### Customer Total Order Count (LOD: FIXED)
Calculates the total number of orders placed by each individual customer.
```tableau
// [Customer Order Count]
{ FIXED [Customer] : COUNTD([Order ID]) }
```
*Business Application: Identifies 100% repeat buyer rate (all 8 customers placed between 5 and 7 orders).*

---

### First Purchase Date (LOD: FIXED)
Finds the acquisition date for each customer to establish customer cohort timing.
```tableau
// [Customer First Order Date]
{ FIXED [Customer] : MIN([Order Date]) }
```

---

### Customer Lifetime Tier (LOD-Driven Dimension)
Segments customers into commercial value groups based on their lifetime spend.
```tableau
// [Customer Tier]
IF { FIXED [Customer] : SUM([Revenue]) } >= 300000 THEN
    "Platinum VIP (₹3L+)"
ELSEIF { FIXED [Customer] : SUM([Revenue]) } >= 100000 THEN
    "Gold (₹1L - ₹3L)"
ELSE
    "Silver (<₹1L)"
END
```
*Output on Dataset:*
- **Platinum VIP**: Aarav (₹5,39,000), Isha (₹3,33,200), Sanya (₹2,50,200)
- **Gold**: Kabir (₹83,500), Diya (₹67,410), Rohan (₹69,920), Arjun (₹58,450), Meera (₹36,750)

---

### Order Basket Size (LOD: FIXED by Order)
Calculates total monetary value per order identifier.
```tableau
// [Order Value (LOD)]
{ FIXED [Order ID] : SUM([Revenue]) }
```

---

### Regional Benchmark Comparison (LOD: EXCLUDE)
Computes the total sales of a region ignoring category breakdowns, allowing you to calculate the category's percentage contribution to that specific region.
```tableau
// [Category % of Regional Sales]
SUM([Revenue]) / SUM({ EXCLUDE [Category] : SUM([Revenue]) })
```

## 3. Table Calculations (Time Intelligence & Rankings)

### Month-over-Month (MoM) Revenue Growth %
Calculates percentage change in revenue between consecutive calendar months.
```tableau
// [MoM Revenue Growth %]
(ZN(SUM([Revenue])) - LOOKUP(ZN(SUM([Revenue])), -1)) 
/ 
ABS(LOOKUP(ZN(SUM([Revenue])), -1))
```
*Compute Using: `Order Date (Month / Year)` along Table (across)*
*Format: Percentage (`+0.0%;-0.0%`)*

---

### Running Cumulative Revenue
Tracks cumulative revenue velocity over time.
```tableau
// [Cumulative Revenue]
RUNNING_SUM(SUM([Revenue]))
```
*Compute Using: `Order Date` along Table (across)*

---

### Product Sales Rank (Dense Ranking)
Ranks products from highest to lowest revenue within each category.
```tableau
// [Product Rank in Category]
RANK_DENSE(SUM([Revenue]), 'desc')
```
*Compute Using: `Product` restarting every `Category`*

---

### Percentage of Total Revenue
Computes the proportion of overall revenue captured by a specific dimension (Category, Region, or Product).
```tableau
// [% of Total Sales]
SUM([Revenue]) / TOTAL(SUM([Revenue]))
```
*Compute Using: `Table (down)` or `Category`*
*Format: Percentage (`0.0%`)*

## 4. Logical & Parameter-Driven Calculated Fields

### Dynamic Metric Selector (Parameter Calculation)
Enables executive end-users to toggle the primary chart between Sales, Volume, and AOV using a single dropdown parameter `[Select Metric]`.
```tableau
// [Dynamic KPI Value]
CASE [Select Metric]
    WHEN "Revenue" THEN SUM([Revenue])
    WHEN "Orders" THEN COUNTD([Order ID])
    WHEN "Units" THEN SUM([Quantity])
    WHEN "AOV" THEN [Average Order Value]
END
```

---

### Order Value Segment (Row-Level)
Classifies individual transactions into ticket sizes for basket mix analysis.
```tableau
// [Order Size Segment]
IF [Revenue] >= 40000 THEN
    "High-Ticket (₹40,000+)"
ELSEIF [Revenue] >= 15000 THEN
    "Mid-Tier (₹15,000 - ₹39,999)"
ELSE
    "Standard (<₹15,000)"
END
```

---

### Payment Follow-Up Status
Highlights uncollected revenue needing commercial remediation.
```tableau
// [Payment Collection Action]
IF [Payment Status] = "Paid" THEN
    "Settled"
ELSEIF [Payment Status] = "Pending" THEN
    "Action: Payment Reminder Required"
ELSEIF [Payment Status] = "Failed" THEN
    "Critical: Failed Checkout Recovery"
END
```
